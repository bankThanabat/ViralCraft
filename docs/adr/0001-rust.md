# ADR-0001: Write the CLI in Rust

## Status
Accepted

## Date
2026-10-09

## Context
The CLI decodes every frame of a video, runs text detection on each, and
transcribes speech. It ships to people who run it through an agent on their
own machine, so it has to install as one binary with few moving parts.
Python has the richest media libraries but brings an interpreter, virtual
environments and pip conflicts to every user.

## Decision
Rust, as one workspace with a crate per stage. OCR is `ocrs` with models
through `rten`; speech is `whisper-rs` (whisper.cpp). Both were verified on
Apple Silicon before the plan was approved.

## Alternatives considered
- **Python** (OpenCV, PySceneDetect, faster-whisper): fastest to write;
  rejected for the install burden on users.
- **Go**: one binary too, but no maintained in-process OCR or whisper
  bindings, so it would shell out for everything.

## Consequences
- One `cargo install`; models download on request through `doctor`.
- Per-frame work is fast enough to run on every frame (about 25 ms per
  frame for text detection).
- `rten` must stay at the version `ocrs` pins, or the model types clash.
- Dev-only checks that need Python (the OTIO round trip) stay in ignored
  tests behind an environment variable.
